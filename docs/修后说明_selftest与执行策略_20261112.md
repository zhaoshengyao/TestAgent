## 3. P0 – 快照解析多算 generic 容器

### 事实

selftest 报："期望 5 个元素，实际 6 个"。

样本：

```
- generic [ref=e1]:
  - heading "Example Domain" [level=1] [ref=e3]
  - textbox "Username" [ref=e5]
  - textbox "Password" [ref=e6]
  - button "Login" [ref=e7]
  - link "Forgot password?" [ref=e8]
```

`parse_snapshot` 把 `generic [ref=e1]` 也当成一个元素抽进来了——6 个 vs 期望 5 个。

### 根因

`generic` 是 accessibility tree 的容器节点，不是可交互节点；它的 ref 在真实页面里也永远不会被模型拿去点击。解析器没有跳过这类容器角色。

### 修法

`stagent/snapshot.py::parse_snapshot` 开头加一个角色黑名单 `SKIP_ROLES = {"generic", "text", "paragraph", "InlineTextBox"}`，遇到这些 role 直接 `continue`。

### 复核判据

- selftest 里 `len(elements) == 5` 通过；
- 在真实 MCP 快照里（含更多 generic/text 节点），被抽出的元素必须是 heading / textbox / button / link 等有实际意义的交互元素。

## 4. P0 – Markdown 报告缺少自愈记录

### 事实

selftest 报 "Markdown 缺少自愈记录"。

自检里我们构造了一条带 `healed=True` 的 StepRecord，也给 `CaseResult` 填了 `healings=[...]` 字段（已修正）。但原来的代码里 `CaseResult.healings` 的数据源是 `healer.events`，而 `healer.events` 只记录 `healer.propose()` 内部发生的事件——如果某次自愈是在 `_run_tool` 里直接触发（不走 `propose`），那条自愈就没有进 `events`，导致报告里看不到。

### 根因

自愈事件有两个来源：`Healer.propose()` 内和 `agent._run_tool` 内（直接触发的自愈）。原来的代码只记录了前一个来源，`_finalize()` 又只聚合 `healer.events`，后者被丢失。

### 修法

引入新文件 `stagent/heal_log.py`，里面一个简单的 `HealLog` 类 + `HealEvent` dataclass：

- `Healer` 不再持有 `self.events`，改为持有 `self.heal_log: HealLog`；每次 `propose()` 里的成功/失败都往 `heal_log.add(HealEvent(...))`。
- `TestAgent.__init__` 里创建一个 `HealLog` 实例，传给 `Healer`；自己也留一份引用。
- `TestAgent._finalize()` 里 `result.healings = self.heal_log.as_dicts()`。
- `cli.py` 超时分支里的 `agent.healer.events` 也改成 `agent.heal_log.as_dicts()`。
- `selftest.py` 里给 CaseResult 补一个真实的 `healings=[...]` 条目，让报告渲染路径走到。

### 复核判据

- selftest 里 Markdown 报告包含"自愈记录"段落和"第1次自愈…"细节；
- 真实用例里触发自愈时，report.html / report.md 里都能看到每条自愈的 ref、reason、confidence。
