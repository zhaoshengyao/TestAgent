## 2. 原文要点拆解

| # | 原文主张 | 真实含义 | 落地 |
| --- | --- | --- | --- |
| 1 | 传统 UI 自动化卡在选择器脆弱 | CSS/XPath 绑实现细节 | parse_snapshot 抽 role + name + ref |
| 2 | 需要意图翻译层 | 把"点击提交"翻译成浏览器操作 | System Prompt 指导模型 |
| 3 | MCP = 手和眼 | 工具暴露 + 上下文快照 | @playwright/mcp 工具 + accessibility tree |
| 4 | 快照过滤精简 | 去 script/style/隐藏元素 | parse_snapshot skip 容器角色 + compact_snapshot |
| 5 | 自愈定位 | ref 失效→重快照→LLM 找替 | Healer.propose → auto retry |
| 6 | 本地 LLM / 内网 LLM | 数据不出本机 / 合规 | AsyncOpenAI 兼容层（Ollama / DeepSeek / 自定义内网） |
| 7 | 约 200 行核心 | 提示词 + 快照压缩 + 自愈 | 本仓库 agent.py 约 410 行（多了 verify 裁判、节流、报告生成） |
| 8 | 核心是 MCP + Playwright + 本地 LLM | 不是 LangChain | 去掉 LangChain 依赖，减少版本漂移 |

**原文没说但关键**（落地后才发现）：

1. MCP 的 `### Page` 区块自动给 Page URL / Page Title / Viewport——不需要调 browser_evaluate。
2. `browser_snapshot` 返回巨型 YAML（几百行），截断给模型能省 60%+ token。
3. 内网网关限流（27B 模型 + 2s 节流）下，重试必须够激进（12 次 + 指数退避封顶 60s）。
4. **自动快照（auto_observe）必须保持开启**——否则 click 后快照历史不追加，断言裁判拿不到操作后的页面证据，会误判。

## 3. 三次冒烟 run 对比

| 指标 | 第一次（1113 上午，全绿） | 事故（1113 下午，误判 failed） | 修复后（1113 傍晚，全绿） |

| 裁判证据通道 | 快照历史 + Page URL | **同左，但快照历史为空**（因为 auto_observe 关了，模型又没显式 snapshot） | 快照历史（auto_observe 自动补）+ Page URL + **步骤 output 原文摘要（兜底）** |
| 报告 | artifacts/runs/*/report.html | artifacts/runs/20261113_152820/report.html | artifacts/runs/fixverify_retest/report.html |

**事故复盘**：Agent 执行本身完全正确——步骤里 browser_find 确实找到了 Products 和 Epic sadface。问题全在裁判：verify 只看 `_snapshot_history[-3:]`，而 auto_observe 关了之后 click 后不会自动补 snapshot，模型自己也没显式调 snapshot，所以裁判拿到的快照只有初始登录页。browser_find 的匹配结果在 step.output 里，但裁判根本不读 step.output。

**修复**：三条通道兜底——快照历史（auto_observe=true 后自动不空）+ Page URL（从未丢过）+ **步骤 output 原文摘要**（新增，所有工具 output 截前 1200 字喂给裁判）。VERIFY_SYSTEM prompt 也更新了，明确告诉裁判 browser_find 匹配也是合法证据。

## 4. 最终架构

```
一句话指令
  ↓
agent.run_instruction() → ReAct 循环（最多 40 轮）
  ├─ llm.chat(messages, tools=25 个 MCP 工具)
  │   └─ 12 次指数退避（2s→4s→…→60s）+ 2s 节流 + Retry-After 尊重
  ├─ bridge.call(name, args) → stdio 调 @playwright/mcp
  │   └─ MCP 返回的 output 含 ### Ran JS / ### Page / ### Snapshot / ### Events
  ├─ agent._render_tool_output → 给模型的那份只删 Snapshot（保留 Page）
  ├─ auto_observe=true → ACTION_TOOLS 后自动补 browser_snapshot 入 _snapshot_history
  └─ StepRecord.output → 完整 output 存下来给 verify grep

跑完后：
  agent.run_case() → verify(证据汇编)
    ├─ 通道1: _snapshot_history[-5:] → compact_snapshot 压缩
    ├─ 通道2: MCP output 里 grep "Page URL: ..." 行
    ├─ 通道3: 所有步骤 output 原文摘要（每步前 1200 字，兜底）
    └─ llm.chat_json(VERIFY_SYSTEM, evidence_text) → 逐条给 passed + evidence

最终：
  write_reports(out_dir, title, results, meta)
    → report.md（人读）+ report.html（带截图缩略图）+ summary.json（流水线读）
```

## 5. 关键设计决策（含与原文的差异）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| LangChain | **不用** | `langchain` / `langchain-mcp-adapters` 版本漂移大、调试链路长，改用官方 `mcp` SDK + `openai` SDK 手写 ReAct |
| MCP 客户端 | 官方 `mcp` SDK（stdio 模式） | 与 Cursor / Claude Desktop 同一条路 |
| 模型协议 | OpenAI 兼容 | Ollama / DeepSeek / 内网 custom 端点一套代码 |
| 断言判定 | **独立第二次 chat**（verify 裁判） | 主循环里的模型有"我做到了"的倾向；裁判只看客观证据，每条必给 evidence |
| 裁判证据汇编 | **三条通道兜底** | 快照历史（auto_observe 自动补）+ Page URL（硬证据）+ 步骤 output 摘要（兜底，browser_find 匹配不丢）。任何一条能佐证就不应该误判 |
| 自愈 | Healer.propose → HealLog | 只修"怎么定位"不改"断言什么"；报告里列自愈事件 |
| 节流 + 退避 | 12 次指数退避 + 2s 节流（均可 config） | 内网网关限流 |
| auto_observe | **默认 true，不要关** | 关掉会导致 click 后快照历史不追加，裁判证据链断裂——1113 下午事故的根因 |
| Page URL 证据 | 从 MCP output 的 `### Page\n- Page URL: ...` grep | 不需要 browser_evaluate |
| Token 优化 | 只截 Snapshot 区块（保留 Page） | Snapshot YAML 巨型，Page 短且给模型当前页状态 |
| 配置优先级 | config.yaml > 进程环境变量 > .env > 默认 | 让 yaml 是项目级权威配置 |

## 8. 当前已知限制（真实踩过的坑）

| # | 限制 | 实际影响 | 要不要规避 |
| --- | --- | --- | --- |
| 1 | **auto_observe=false 会炸裁判** | 1113 下午事故：动作后快照历史不追加，裁判拿不到操作后的页面证据 | **必须保持 true**，别为了省一点 token 关它 |
| 2 | **快照 ref 时效性** | ref 跨快照失效是 Playwright MCP 设计使然，自愈能救但多花一次 LLM | 正常现象，接受 |
| 3 | **自愈边界** | 只覆盖"元素还在、定位方式变了"；整块 UI 改版（流程都变了）自愈无效 | 改版时人工改 instruction |
| 4 | **小模型工具调用不稳** | 7B/8B 级可能忘传 ref 或一次塞多个动作 | 提示词约束 + 自愈已兜底，但仍建议 27B 以上或云端 |
| 5 | **成本与速度** | 本地模型近乎零成本但 90–200s/用例；云端快但烧 token | `tool_result_char_limit` + `max_steps` 控闸 |
| 6 | **安全** | Agent 真实点击真实按钮 | 生产前限账号权限，禁止资金类操作 |
| 7 | **HTML 报告截图路径** | 用相对路径，移动报告目录会丢图（截图仍在 `artifacts/screens`） | 报告目录和截图一起动 |

### 变量解析规则

```yaml
# 顶层：外部 + 内联合并
data_from: saucedemo_users.yaml   # 先合并外部
data:
  site_name: Saucedemo            # 再合并内联（覆盖外部同名 key）

cases:
  - name: 某个场景
    data:
      username: "{{users.locked_out.username}}"   # Case 级再覆盖
      password: "{{users.locked_out.password}}"
    instruction: |
      用 {{username}} / {{password}} 登录
      （{{username}} 先查 Case.data，没找到再查 Suite.data）
    assertions:
      - "页面出现 {{username}} 的登录结果"   # assertions 也渲染
    url: "{{site_name}}/inventory.html"    # url 字段也渲染
```

- 渲染时机：`load_suite` 阶段一次性替换，agent / cli 拿到的 instruction 已是最终字符串。不涉及运行时再展开。
- 缺失变量：渲染为 `""`（空串），**不报错**。模型看到的指令里会出现"登录 / 登录"，但不会崩溃。需要兜底时写 `{{var|default('fallback')}}`。
- `{{data.var}}` 和 `{{var}}` 等价——`_lookup` 自动剥掉首段 `data`。
- list / dict 嵌套结构在字符串里渲染时转 YAML compact 形式（`{{goods}}` → `[Backpack, T-Shirt]`）。

### Case 级 data_from 也支持
单 case 可以有自己的 `data_from:`，加载顺序：Suite.data_from → Suite.data → Case.data_from → Case.data（后者覆盖前者）。当前 demo 还没用到，但已留好。

### selftest 新增 5 组单测覆盖

```
✅ data 内联合并与渲染        — Case 覆盖 Suite / 点号引用 / 缺失空渲染
✅ data_from 外部合并          — 真实 saucedemo_users.yaml 合并进 suite.data.users
✅ 模板 default 管道          — {{b|default('BX')}} 对缺失变量兜底
✅ 模板 list/dict 结构渲染    — 列表字段在 instruction 里展开
✅ 真实 suite 变量渲染        — smoke 2 条 / demo 4 条 / locked_out.username / 断言渲染
```
