## 目标定义

> **生产级 = 改完代码后 5 分钟内自动告诉你：哪些用例回归了、是 agent 坏了还是真页面坏了、哪些 fail 是预期的 bug 探测不用慌。**

不追求"全绿 0 fail"——因为 problem_user / error_user / performance_glitch_user 这些账号**就是用来测页面 bug 的**，它们 fail 本身就是产出。生产级要解决的是：
1. **预期 fail 和意外 fail 分开记账**——problem_user fail 不算红线，standard_user fail 算
2. **改完代码立刻能知道有没有引入新回归**——CI 门禁
3. **失败自动分类根因**——agent 策略缺陷 / 前端 bug / 断言裁判问题，一眼看

## 已知约束（不变）

1. **MCP 工具能力上限**：`browser_fill_form` 在 problem_user 上失效，`browser_type` 能生效——框架级策略重试（Phase 1.5）必须基于 MCP 工具真实行为差异，不能假设所有工具对所有账号都等价
2. **429 限流**：当前内网 429 需要 12 次指数退避 + 2s 节流；CI 跑云端 API 时节流参数要降到 3-5 次
3. **agent 是 LLM 驱动**：每次跑可能有微小差异（比如某步 browser_find 换了 regex），CI 门禁比较基于"passed/skipped/unexpected 汇总"不是"步骤序列完全一致"
4. **策略重试的边界**：Phase 1.5 的自动 retry 只在"fill_form 成功但 Continue 报 error"时触发——不能在"fill_form 直接返回 Error"时就 retry，因为 MCP 工具返回 Error 可能是 selector 找不到（自愈应该先触发）
