# 调试复盘：断言裁判与循环治理（2026-11-13 ~ 11-16）

> 背景：demo_checkout（购物车→结算→下单）用例连续 13 轮改动才收敛。本文沉淀每轮改动的性质、失败根因与最终修复，避免后续重复踩坑。

---

## 一、最终稳定所需的核心修复（全部保留）

| # | 修复 | 位置 | 解决什么 |
|---|---|---|---|
| 1 | verify 三条证据通道 | `stagent/agent.py::run_case` | 快照历史 + Page URL + 各步骤 output 原文摘要（每步前 1200 字）。只靠快照历史会在 auto_observe=false 或模型没显式 snapshot 时断链 |
| 2 | `auto_observe: true` | `config.yaml` | 关掉后 click 后快照历史不追加 → 裁判拿不到操作后页面 → 误判 failed |
| 3 | 自愈时清 target | `stagent/healer.py` | browser_click/type/hover/select_option/drag 这 5 个 ref-only 工具，自愈换 ref 时必须 `pop("target")`，否则旧 CSS 选择器残留导致自愈白换 ref |
| 4 | 每个 case 独立 MCP bridge | `stagent/cli.py::_execute` | bridge 启动/关闭移进 case 循环内。共享浏览器会让 Case 1 的 session 污染 Case 2 |
| 5 | `--isolated` | `config.yaml browser.extra_args` | Playwright MCP 默认持久化 profile，浏览器进程重启但 localStorage/cookies 落盘残留——购物车状态跨 run 泄漏，造成"时好时坏"的随机性。链路：`config.py pick("browser","extra_args")` → `mcp_bridge.py _build_args` → `StdioServerParameters` |
| 6 | 循环检测两层 | `stagent/agent.py` | 软提示 `record.loop_hint` 由 `_render_tool_output` 渲染（带 ⚠️ 前缀、截断时拼回末尾保证送达）；硬拒绝 `_loop_streak >= 4` 时 `run_instruction` 直接 return 终止。相似判定 = regex/text 归一化（`{0,500}`→`{0,N}`）+ 输出同为 success/同为 empty |

## 二、关键教训（每条都真实踩过）

### 1. 检测和投递是两回事

循环检测触发 25 次但 hint 写进 `record.output`（报告字段），模型上下文走 `_render_tool_output(result.text)`——**模型一次都没看到**。改了三轮检测逻辑全部无效，直到反问"模型到底收到了什么"才发现投递路径是断的。

**规则**：任何"给模型的提示"，必须验证它出现在 `_render_tool_output` 的返回值里。

### 2. instruction 里不要写"确认状态"类步骤

"确认购物车角标显示 2"这种步骤是死循环诱因：模型 find "cart" 匹配到 "Add to cart" 按钮文本，永远确认不了数字。**状态确认交给 verify 裁判的断言证据，执行期模型只管推进流程。**

### 3. 断言必须符合站点实际行为

Saucedemo 空购物车时 Checkout 按钮不禁用、Finish 可点且能生成 $0 订单。写断言前先确认站点行为，别写"应该怎样"。

### 4. 多 case 共享浏览器 = 级联故障

Case 1 搞坏 session（登录态错乱、加购残留、ref 漂移）会把 Case 2 一起拖下水，且 Case 2 的失败根因看起来和它自己的操作无关。隔离是标配。

### 5. 失败后先问"模型收到了什么"，再改 prompt

改 SYSTEM_PROMPT 12 条规则是软手段，模型不是规则引擎。prompt 规则保留（有生效案例：规则 11 让冒烟 Case 2 从 bug regex 循环变成正确搜 "Epic sadface"），但结构性问题必须代码层兜底。

### 6. ops_bash 不可靠时的验证方式

DSH 会话里 ops_bash 出现过"exit 0 但无输出、Python 根本没执行"。此时改动验证靠：
- AST parse：`python -c "import ast; ast.parse(open('file.py', encoding='utf-8').read())"`
- 真实 run 的 summary.json / report.md 反向取证
- 子代理独立复核

## 四、跑法

```powershell
python -m stagent run suites/demo_checkout.yaml --out artifacts/runs/<名字>
python -m stagent run suites/smoke_login.yaml --out artifacts/runs/<名字>
```

判断标准：
- Case 1：加购 → 进购物车 → Checkout → Finish → Thank you，三断言全绿
- Case 2：空购物车 → Checkout → 汇总页 $0.00，两断言全绿
- 若模型再刷 find：第 2 次收到 ⚠️ 提示，第 4 次强制终止，报告干净显示"循环终止"
